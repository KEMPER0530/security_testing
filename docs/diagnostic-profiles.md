# 診断の選び方とPDFレポート

## 通常のWeb公開設定診断

URLを登録し、常時表示される「Web診断」カードを選んで「Web診断を開始 →」を押すと、公開1ページのTLS・応答ヘッダー・Cookie属性・静的HTMLを確認します。所有確認ファイルやシステム重要度の事前入力は不要です。

## 5種類のカードから選択

診断対象を選び、Web診断・ペネトレーション（限定検証）・ネットワーク診断・AWSホスト診断・AWSクラウド診断のカードを選択します。メニューを開く操作は不要です。カードには検査内容の要約と、選択対象の種類別履歴件数を表示します。

選択後は検査項目を指定し、表示された対象・範囲について実施権限を確認して「種類名を開始 →」を押します。受付後は非同期処理し、同じ種類の結果・履歴からPDFを取得できます。履歴一覧は初期表示で「すべての対象」を新しい順に表示し、「履歴の表示範囲」で選択中の対象だけに絞れます。各行からその履歴の結果・PDFを選びます。カードの「この対象の履歴」は選択中の対象の件数です。種類を切り替えると、その対象・種類に一致する保存結果を表示します。履歴には選択中の診断種類だけを表示し、別種類の履歴は混在させません。履歴がない種類には他種類の結果を表示しません。

結果はWebの保護設定、HTTP検証、TCPポートと接続状態、EC2のOS収集状態・既知脆弱性、AWSリソースの設定に分けます。表示する検査範囲は実行時に保存した種類・項目・ポート・リソースに基づきます。ペネトレーションで公開設定も選ぶとWeb診断と同じ保護設定の指摘が出る場合があります。その部分は「Web診断と共通」と表示し、CORS・OPTIONS・TRACEとは分けます。

| 種類 | このアプリで実行すること | 実行しないこと |
|---|---|---|
| ネットワーク（限定） | 公開DNS応答、選択したTCPポートへの接続、登録URLのWeb/TLS確認 | 全ポート探索、OS・製品推定、サービスの既知脆弱性検査 |
| ペネトレーション（限定検証） | 公開設定、固定検証OriginによるCORS応答、OPTIONSの許可表示、秘密情報を含まないTRACE反射 | 認証突破、SQL等の入力攻撃、任意ペイロード、データ変更、侵入・権限昇格・横展開 |
| AWSホスト | 指定EC2のSSM接続・Inventory収集状態、Inspectorの既存検出とCVSS | OSコマンド、SSM SendCommand、SSH接続、新規のInspector検査開始 |
| AWSクラウド | アカウントのルートMFA、指定S3の公開防止・既定暗号化、指定SGの全世界向け管理/DBポート許可、指定CloudTrailの記録状態 | ファイル内容の取得、設定変更、全リソース探索、クラウド全体の準拠保証 |

これらは初期調査の限定機能です。[CybertrustのWebアプリケーション診断](https://www.cybertrust.co.jp/security-diagnosis/web-application.html)や[ペネトレーションテスト](https://www.cybertrust.co.jp/security-diagnosis/penetration/)のような、入力値・認証・業務操作や実際の攻撃経路を含む専門家の包括的検証と同じ範囲を提供するものではありません。

公開管理ポートに接続できても、それだけでは脆弱性や侵入成功と断定しません。OPTIONSのAllow表示だけで、書き込み操作が可能とも判定しません。

## AWS接続の初回準備

1. 対象を選び、AWSホストまたはAWSクラウドを選択して「AWS接続を準備・設定を表示」を押します。
2. 接続用CloudFormationテンプレートをダウンロードし、診断対象のAWSアカウントで管理者がスタックを作成します。IAMロール作成の承認が必要です。
3. スタックの出力にあるRoleArnを画面に貼り、保存します。保存時点では接続未検証です。
4. リージョンと対象リソースを指定し、検査範囲を確認して実行します。診断開始時にロールの信頼条件と接続を検証します。

アクセスキーやパスワードはアプリに登録しません。読み取り専用ロールと、利用者・登録対象ごとにサーバーで生成したExternalIdを使用します。ExternalIdなし・別のExternalIdでも引き受け可能なロールは拒否します。AWSの[第三者アクセスとExternalIdの推奨手順](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_common-scenarios_third-party.html)に従います。

テンプレートの権限は診断で使用する列挙済み読み取り操作に限ります。リソース指定ができないDescribe/List操作を含むためResourceは`*`です。APIは選択された識別子に限定してリクエストします。S3はExpectedBucketOwnerも指定します。ロールの引き受け時に読み取り専用セッションポリシーを重ね、誤って強い権限のロールを指定しても変更操作を許可しません。不要になった接続ロールは対象AWSの管理者が削除してください。

検査対象のAWSアカウント管理者の設定が必要です。他人のサイトの内部AWS情報を、公開URLだけから取得することはできません。対象URLは履歴の整理用ラベルであり、指定AWSリソースと同じシステムであることを自動認定しません。

## 実行上限と不完全な情報

- TCPは対応する11種類から最大8個。AWSリソースは種類ごとに最大3個。登録ホストと指定リソースだけを対象にします。
- SSM InventoryとInspectorは既存の収集情報です。7日以内の収集・有効状態を確認し、古い・未収集・取得不能な状態は「確認不能」「未実施」とします。OSの脆弱性がないことの保証ではありません。
- Inspectorは1台につき深刻度順に最大10件を取得します。続きがある場合は「確認不能」と明記し、Inspectorで残りを確認するよう案内します。
- AWS通信は接続1秒・応答2秒・自動リトライなし、処理全体の予算40秒です。時間切れ・権限不足の項目を「指摘なし」にしません。
- 受付間隔60秒、同時受付2件、ホスト待機120秒、既存のキャンセル・削除フェンスを適用します。同じ対象でも検査範囲やAWS接続ロールが違う履歴は差分比較しません。Inspectorの検出には検出ARNと対象EC2から安定した識別子を作り、並び順が変わっても新規/継続を取り違えません。

## IPAを参照したPDF

診断履歴の「PDF ↓」から出力します。保存結果を使い、PDF出力時に再検査しません。

結果概要、診断結果一覧、IPA節との対応表、項目ごとの説明・判定根拠・改善方法・CVSSを表中心の診断レポートとして出力します。日本語フォントを埋め込み、ヘッダーとページ番号を付けます。

[IPA「安全なウェブサイトの作り方」改訂第7版（2021年3月）](https://www.ipa.go.jp/security/vuln/websecurity/ug65p900000196e2-att/000017316.pdf)の第1章11節・第2章2.1〜2.3を独自に要約しています。IPA資料の全項目を転載したものではありません。関連ヘッダーを観測しても、SQL処理・認証・権限などの根本的対策を検証済みにしません。Web・限定Web検証のPDFにIPA対応表を掲載します。ネットワーク・AWSホスト・AWSクラウドにはWeb向けIPA表を掲載せず、選択したポートやAWS対象と実測結果を表示します。IPA認証・完全準拠を表示しません。

CVSSは、公開設定に対する条件付きv4.0参考評価と、Inspectorが提供した既知脆弱性の評価を区別します。提供元・バージョン・ベクトルを保持し、計算結果と一致しないスコアや不正なベクトルには数値を付けません。設定情報だけで悪用条件が分からない所見は「適用外」と理由を表示します。
